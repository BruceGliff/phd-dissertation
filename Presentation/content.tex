\begin{frame}
  \frametitle{Теория трасс}
  Теория трасс~\cite{mazurkiewicz1986trace} -- математическая основа
  описания конкурентного
  исполнения:
  \begin{itemize}
    \item алфавит действий $\Sigma$ и~отношение \textbf{зависимости}
      $D$ (порядок важен) либо \textbf{независимости}
      $I$ (перестановка не~изменяет результат);
    \item трассы -- классы эквивалентности строк, отличающихся лишь
      перестановкой соседних независимых действий;
    \item алгоритмы частичного/динамического сокращения порядка
      (POR/DPOR) обходят ровно по~одному представителю от~каждой трассы.
  \end{itemize}
  \begin{alertblock}{Ограничение}
    Модель памяти задаёт здесь лишь отношение зависимости; среди
    порождаемых кандидатов могут быть исполнения, нарушающие аксиомы
    модели, они исключаются только на~последующей проверке.
  \end{alertblock}

  \fixme{пример задания алфавита, множества I, D и формулу.
    \begin{equation}
      ab \equiv_D ba
    \end{equation}
  }.
\end{frame}

\begin{frame}
  \frametitle{Обоснование необходимости нового решения}
  {\footnotesize
    \setlength\itemsep{1.5pt}
    \begin{itemize}
      \item задача построения всех возможных состояний системы после
        исполнения многопоточной программы ялвяется $\$P$-полной,
        поэтому прямое построение сталкивается с комбинаторным взрывом
        ($n!$ в худшем случае);
      \item для преодоления этого ограничения, существующие решения
        накладывают существенные ограничения на структуру теста:
        отсутствие частичного пересечения адресов в памяти,
        предзаданное строгое взаимодействие операций (Операция -
        Локация - Значение), либо существенное ограничение количества
        операций с памятию в многопоточной программы;
      \item без ограничения общности состояние системы определяется
        множеством операций с~памятью
        и~их~порядком; задача анализа сводится к~построению линейных порядков
        частично упорядоченного множества;
      \item при этом многие перестановки приводят систему в~одно и~то же
        состояние -- их~не~требуется анализировать.
    \end{itemize}
    \vspace*{-0.9em}
    \begin{block}{Вывод}
      Необходимо использовать наиболее общее представление
      многопоточной программы, чтобы ослабить ограничения существующих
      подходов, а также необходимо учесть перестановки, приводящие
      систему в одно и то же состояние, чтобы преодолеть комбинаторный взрыв.
    \end{block}
  }
\end{frame}

\begin{frame}
  \frametitle{Отличие предложенного подхода}
  В~работе разделены два понятия, которые теория трасс объединяет:
  \begin{description}
    \item[Частичный порядок $P$] задаёт ограничения, накладываемые
      моделью памяти на~допустимый порядок операций;
    \item[Отношение зависимости $D$] определяет значимые варианты
      взаимного порядка операций (классы эквивалентности перестановок).
  \end{description}
  \begin{block}{Ключевое свойство}
    Линейные порядки строятся \textbf{с~учётом аксиом модели памяти},
    поэтому недопустимые кандидаты (нарушающие аксиомы) не~порождаются
    по~построению, в~отличие от~подходов на~основе теории трасс.
  \end{block}
\end{frame}

\begin{frame}
  \frametitle{Частично упорядоченное множество операций с памятью}
  \begin{block}{Математическая модель}
    Многопоточная программа представляется в~виде частично упорядоченного
    множества операций с~памятью, построенного
    с~учётом выбранной модели памяти.
  \end{block}
  \begin{itemize}
    \item Каждая операция с~памятью ($R$, $W$, $RMW$, $F$) -- элемент
      множества: \[P : \forall x \in P \equiv x \text{ -- операция с
      памятью} \]
    \item Порядок задаётся программным порядком и~ограничениями модели
      памяти: \[<_p : \forall x, y \in P \mid x <_p y \equiv xy
      \text{ -- PPO}\]
  \end{itemize}
\end{frame}

\begin{frame}
  \frametitle{Обход частично упорядоченного множества топологической
  сортировкой}

  \begin{columns}[T, onlytextwidth]
    % Left column, width 48% of text width
    \begin{column}{0.6\textwidth}
      \label{alg:topo}
      \begin{algorithmic}[1]
        \Require $P$ -- частично упорядоченное множество.
        \Require $\pi$ -- текущий линейный порядок.
        \Require $ctx$ -- контекст алгоритма обхода.
        \Function{Traverse}{$P$, $\pi$, $ctx$}
        \If{$P = \emptyset$}
        \State $L(P) \gets \pi \cup L(P)$
        \EndIf
        \ForAll{$\forall x \in \min(P)$}
        \State $r \gets$ \Call{Process}{$ctx$, $\pi$, $x$}
        \If{$r == \text{Next}$}
        \State \Call{Traverse}{$P \setminus \{x\}$, $\pi
        \stackrel{add}{\longleftarrow} x$, $ctx$}
        \ElsIf{$r == \text{Break}$}
        \State \Return
        \EndIf
        \EndFor
        \EndFunction
      \end{algorithmic}
    \end{column}

\begin{frame}
  \frametitle{Верификация результата исполнения многопоточной
  программы по линейным порядкам}

  \begin{block}{Условие корректности}
    Существует линейный порядок $\pi$ из множества всех
    допустимых линейных порядков $L(P)$, который приводит систему в
    состояние, наблюдаемое при исполнении исследуемой программы

  \end{block}

  \begin{equation}
    \label{eq:verif-base}
    \exists \pi \in L(P) \mid \forall x \in P,\; reg_{\pi}(x) \in trace
  \end{equation}
  $reg_{\pi}(x)$ обозначает значение, прочитанное операцией $x$ в
  линейном порядке $\pi$, а $trace$ -- множество всех прочитанных
  значений, зафиксированных при фактическом исполнении программы.

  \note{
    Верификация корректности исполнения программы заключается в поиске
    такого линейного порядка операций с памятью, который приводит
    многопроцессорную систему в то же состояние, что и наблюдаемое при
    фактическом исполнении исследуемой многопоточной программы.
  }

\end{frame}

\begin{frame}
  \frametitle{Учёт зависимости/независимости операций}
  \begin{block}{Определение}
    Операции $A$ и~$B$ \textbf{независимы}, если исполнение в~порядке
    $A$--$B$ приводит систему в~то~же состояние, что и~$B$--$A$.
    Иначе они \textbf{зависимы} ($\{A, B\} \in D$).
  \end{block}
  \begin{itemize}
    \item $B^{|}$ -- отношение эквивалентности между
      независимыми операциями,
      $Eq^{|}(\pi, B^{|})$ -- класс эквивалентности перестановки
      $\pi$ относительно $B^{|}$: $102 \in
      Eq^{|}(\pi, B^{|})$, где $B^{|} = \{\{01, 10\}, \{02, 20\}\}$, $\pi=012$;
    \item применение цепочки последовательных эквивалентных перестановок
      порождает перестановку, эквивалентную исходной:
      $012 \stackrel{Eq(\pi, B^{|})}{=} 102 \stackrel{Eq(\pi,
      B^{|})}{=} 120$; $\Rightarrow 012 \stackrel{Eq(\pi, B)}{=} 120$,
      где $B = \{012, 120\} \cup B^{|}$ (``теорема о проекции'').
    \item различные порядки независимых операций приводят в~неразличимые
      состояния -- достаточно анализировать \textbf{одного представителя}
      от~каждого класса эквивалентности;
  \end{itemize}
  \note{
    таким образом, задача сводится к построению всех классов эквивалентности
  }
\end{frame}

\begin{frame}
  \frametitle{Обход частично упорядоченного множества с учётом
  независимых последовательностей операций}

  \label{alg:topo-indep-lookup}
  \begin{algorithmic}[1]
    \Require $B^{|}$ -- разбиение из независимых элементов.
    \Require $\mathcal{B} = \{B_n\}$, где $B_n$ -- множество из
    разбиений на $n$-ом шаге рекурсии. $\mathcal{B}(n) = B_n$
    \Require $y$ -- вершина, обработанная на предыдущем шаге рекурсии.
    \Function{Traverse}{$P$, $B^{|}$, $\mathcal{B}$, $\pi$, $y$, $ctx$}
    \If{$P = \emptyset$}
    \State $L(P) \gets \pi \cup L(P)$
    \EndIf
    \State $\mathcal{B}(n) \gets \emptyset$
    \State $\mathcal{B}(n-1) \gets \mathcal{B}(n-1) \cup \{\{xz,
      zx\} \in B^{|} \mid \forall z \in P,\ \forall x \mid \{xy, yx\}
    \in \mathcal{B}(n-2)\}$
    \ForAll{$\forall x \in \min(P) : \textcolor{blue}{\{xy,
        yx\} \not \in
    \mathcal{B}(n-2)}$}\label{alg:line:traverse}
    \State \Call{Process}{$ctx$, $\pi$, $x$}
    \State \Call{Traverse}{$P \setminus \{x\}$, $B^{|}$,
    $\mathcal{B}$, $\pi \stackrel{add}{\longleftarrow} x$, $x$, $ctx$}
    \If{$\{xy, yx\} \in B^{|}$}
    \State $\mathcal{B}(n-2) \gets \{xy, yx\} \cup \mathcal{B}(n-2)$
    \EndIf
    \EndFor
    \EndFunction
  \end{algorithmic}

\end{frame}

\begin{frame}
  \frametitle{Обход частично упорядоченного множества с учётом зависимостей}

  \label{alg:topo-dep}
  \begin{algorithmic}[1]
    \Require $D$ — множество зависимых элементов.
    \Function{Traverse}{$P$, $D$, $\pi$, $ctx$}
    \State \textcolor{blue}{$X \gets \{ x \in \min(P) \}$} \label{alg:line:X}
    \If{$X = \emptyset, P \not = \emptyset$}  \label{alg:line:loop}
    \State \Return \Comment{Найден цикл}
    \EndIf
    \If{$\{x, y\} \not \in D \mid \forall x \in X, \forall y \in P$}
    \State \Call{ProcessSet}{$ctx$, $X$, $\pi$} \Comment{Обработка
    множества $X$}
    \State \Call{Traverse}{$P \setminus X$, $D$, $\pi
    \stackrel{add}{\longleftarrow} X$, $ctx$}
    \EndIf
    \ForAll{$\forall x \in X, \forall y \in P \mid \{x, y\} \in D$}
    \State $D^{*} \gets D \setminus \{x, y\}$
    \State $P^{\rightarrow} \gets P \cup (x <_{p} y)$ \label{alg:line:pright}
    \State $P^{\leftarrow} \gets P \cup (y <_{p} x)$ \label{alg:line:pleft}
    \State \Call{Traverse}{$P^{\rightarrow}$, $D^{*}$, $\pi$, $ctx$}
    \State \Call{Traverse}{$P^{\leftarrow}$, $D^{*}$, $\pi$, $ctx$}
    \EndFor
    \EndFunction
  \end{algorithmic}

\end{frame}

\begin{frame}
  \frametitle{Комбинаторный взрыв}

  Недетерминизм порядка исполнения операций с памятью во время
  исполнения многопоточной программы порождает большое количество
  возможных состояний многопроцессорной системы.
  Сложность алгоритмов построения всех возможных порядков операций
  с памятью, реализующих все состояния системы, растёт
  экспоненциально, в
  то же время рост количества всевозможных состояний также является
  экспоненциальным.

  \begin{alertblock}{}
    Для верификации всех состояний одной многопоточной программы
    необходимо выполнить \textcolor{blue}{$2^n$} проверок
    \textcolor{blue}{$2^n$} раз.
  \end{alertblock}
\end{frame}

\begin{frame}
  \frametitle{Путь}
  \begin{block}{Решение}
    Необходимо \textbf{сохранение} результата алгоритмов обхода.
  \end{block}

  Для элемента $x$ в порядке $\pi \in L_P$ определим:
  \begin{itemize}
    \item $V_\pi = \{x\} \cup \{y \mid \#_{\pi}(y) <
      \#_{\pi}(x),\ \forall y \in \pi\}$ ;
    \item $E_\pi = \{(b, a) \mid \{a, b\} \in D \text{ или } a <_p
        b,\ \text{где } \#_{\pi}(a) < \#_{\pi}(b),\ \forall a,b \in
      V_\pi\}$.
  \end{itemize}

  \begin{block}{Определение}
    \textbf{Путём} $\rho$ элемента $x$ для порядка $\pi$ назовём
    подпорядок, состоящий из элементов $Y \subseteq \pi$, для которых
    существует простая цепь из $x$ в $\forall y \in Y$:
    \begin{equation}
      \begin{aligned}
        \rho = \{y \in \pi \mid \exists (x, y) \text{ — простая цепь от
        вершины } x \text{ в вершину } y\}, \\
        \text{при этом относительный порядок элементов в } \rho \text{
        такой же, как в } \pi.
      \end{aligned}
      \label{eq:def_suborder}
    \end{equation}
    Обозначается $\rho_{\pi}(x)$.
  \end{block}

  \note{
    $V_\pi$ -- множество вершин, находящихся ``левее'' элемента $x$
    $E_\pi$ --  множество направленных рёбер ``справа налево'' между
    зависимыми элементами или элементами, связанными отношением порядка.

    По построению граф $G_\pi = (V_\pi, E_\pi)$ является ориентированным
    и ацикличным. В таком графе для элемента $x$ существуют простые цепи
    (без циклов), в которых все вершины и рёбра различны~\cite{graph-theory}.

    Иными словами, $\rho_{\pi}(x)$ можно интерпретировать как порядок
    только тех операций, от которых зависит состояние операции $x$.
  }
\end{frame}

\begin{frame}
  \frametitle{Граф состояний}
  \begin{block}{Определение}

    \textbf{Графом состояний} $SG$ (state graph) называется
    ориентированный граф, построенный по правилу~\ref{eq:sg_def}:
    \begin{equation}
      \begin{aligned}
        &V_{SG} = \{ \rho_{\pi}(x) \mid (x, \pi) \in P \times L_P \}, \\
        &E_{SG} = \{ (\rho_{\pi}(x), \rho_{\pi}(y)) \mid (x, y) \in
        E_\pi,\ \forall \pi \in L_P,\ \forall x, y \in P \}, \\
        &SG = (V_{SG}, E_{SG}).
      \end{aligned}
      \label{eq:sg_def}
    \end{equation}

  \end{block}

\begin{frame}
  \frametitle{Верификация результата исполнения многопоточной
  программы по графу состояний}

  \begin{block}{Определение}
    \textbf{Маркированные} вершины графа: $\mathcal{M} =
    \{\rho_{\alpha}(x) \in V_{SG} \mid reg_{\alpha}(x) \in trace\}$.
  \end{block}

  Условия корректности исполнения многопоточной программы:
  \begin{itemize}
    \item \textbf{первое условие корректности}: все операции с
      памятью в многопоточной программе промаркированы;
      \begin{equation}
        \label{eq:verif-1st}
        \forall x \in P\ \exists \alpha \in L_P \rightarrow
        \rho_{\alpha}(x) \in \mathcal{M}
      \end{equation}
    \item \textbf{второе условие корректности}: существует множество
      путей из истоков графа состояний,
      покрывающее все маркированные вершины графа
      \begin{align}
        \label{eq:verif-2nd}
        & visited = \{\text{bfs}(l) \mid \forall l \text{ —
          исток},\ \forall \rho \in \text{bfs}(l) \rightarrow \rho \in
        \mathcal{M}\}, \nonumber \\
        & \text{исполнение программы корректно, если } op(visited) = P.
      \end{align}
  \end{itemize}

  \note{
    Во время исполнения многопоточной программы операциям с памятью
    ставится в соответствие значение, прочитанное данной операцией. Эти
    значения отражаются на графе состояний с помощью

    Из условий корректности верификации по графу состояний
    \ref{eq:verif-1st} и \ref{eq:verif-2nd} следует условие
    корректности верификации по линейным порядкам~\ref{eq:verif-base}
  }
\end{frame}

\begin{frame}
  \frametitle{Кластеризация}

  \begin{equation}
    \label{eq:unorder_set}
    \begin{aligned}
      &G_{unorder} = (V, E), \\
      &V \text{ -- множество операций с памятью,} \\
      &E = \{\{x, y\} \mid \{x, y\} \in D \text{ или } x <_P y \text{
      или } y <_P x \}.
    \end{aligned}
  \end{equation}

  \begin{itemize}
    \item
      \textbf{Кластером операций $C_{i}$} называется множество вершин из
      $i$-й компоненты связности $U_i$ графа $G_{unorder}$:
      \begin{equation}
        C_{i} = V(U_i)
        \label{def:set_cluster}
      \end{equation}

    \item

      Вершины графа состояний для одного линейного порядка $\pi$,
      состоящие только из операций с памятью, принадлежащих одному
      кластеру операций, будем называть \textbf{кластером состояний
      $C_{i}^{\pi}$}:
      \begin{equation}
        \forall \pi\ \exists C_{i}^{\pi} = \{ \rho_{\pi}(x) \mid x \in C_{i}\}.
        \label{def:st_cluster}
      \end{equation}
  \end{itemize}

  \note{
    Стоит отметить, что любая вершина, достижимая из вершины $x$,
    принадлежащей кластеру состояний $C_i^\pi$, также принадлежит
    $C_i^\pi$ (см. формулу~\ref{eq:state_cluster_property}):
    \begin{equation}
      \label{eq:state_cluster_property}
      \forall C_i^\pi\ \forall s \in C_i^\pi \rightarrow \text{bfs}(s)
      \subseteq C_i^\pi.
    \end{equation}
    То есть все вершины кластера состояний достижимы алгоритмом обхода в
    ширину bfs из истоков, принадлежащих этому кластеру.
  }
\end{frame}

\begin{frame}
  \frametitle{Верификация по кластерам состояний}

  $C = \{C_i\}$ -- множество всех кластеров операций.

  $S_i = \{C_i^{\pi} \mid \forall \pi \in L_P\}$ -- множество всех
  кластеров состояний для данного кластера операций.

  \begin{block}{Кластеризованное условие корректности}
    Для каждого кластера операций существует
    хотя бы один маркированный кластер состояний:
    \[
      \forall S_i\ \exists
      C_i^\pi \subseteq \mathcal{M}.
    \]
  \end{block}

  \note{
    Если кластер состояний является подмножеством множества
    маркированных вершин $\mathcal{M}$, то такой кластер состояний будем
    называть \textbf{маркированным}.

    Выполнение кластеризованного условие корректности условия
    обеспечивает соответствие исполнения
    многопоточной программы заданной модели памяти.
  }

\end{frame}

\begin{frame}
  \frametitle{Ограничения}

  \begin{itemize}
          \item
обобщённый подход к~анализу многопоточной программы в~некоторых
краевых случаях всё ещё сводится к~задаче построения \textbf{всех
перестановок без повторений}, при которых асимптотики всех алгоритмов приближаются к $N!$;
          \item
          исключается возможность построения линейных, недопустимых данной моделью памяти, что делает невозможным использовать данных подход при рассмотрении \textbf{негативных} сценариев тестирования;
          \item
          не были рассмотренны data/address/control-зависимости в аксиомах модели памяти.
  \end{itemize}

  \note{
    сказать, что data-address легко реализовать
  }

\end{frame}

\begin{frame}
  \frametitle{Обход ЧУМ с~учётом зависимостей ($topo$-dep)}
  Алгоритм~\emph{topo-dep} направляет неориентированные рёбра зависимости
  на~каждом шаге рекурсии:
  \begin{itemize}
    \item если никакие пары минимальных элементов не~зависимы, множество
      $\min(P)$ обрабатывается целиком;
    \item иначе пара $\{x, y\} \in D$ разъединяется на~два направления
      ($x <_{p} y$ и~$y <_{p} x$), порождая \textbf{бинарное дерево} обхода;
    \item направление, приводящее к~циклу, отбрасывается; множество~$D$
      минимизируется за~счёт отношений порядка.
  \end{itemize}
  \begin{alertblock}{Асимптотика}
    Количество направлений --- $2^{|D|}$; сложность
    $O(2^{|D|} \cdot n^2)$.
  \end{alertblock}
\end{frame}

\begin{frame}
  \frametitle{Сравнение алгоритмов построения линейных порядков}
  Число линейных порядков с~учётом эквивалентности существенно меньше
  полного:
  \begin{center}
    \begin{tabular}{ccc}
      \toprule
      \textbf{Размер} & \textbf{Все порядки} & \textbf{С~учётом
      эквивалентности} \\
      \midrule
      4   & 12            & 3          \\
      9   & 105           & 20         \\
      16  & 2\,041\,200   & 196        \\
      20  & $\approx 1.04\cdot10^{12}$ & 38\,433 \\
      28  & $\approx 6.6\cdot10^{18}$  & 61\,881  \\
      \bottomrule
    \end{tabular}
  \end{center}
  \begin{itemize}
    \item Учёт зависимостей выигрывает при~$p_{D} \lesssim 0.5$, учёт
      независимости --- иначе; выбор алгоритма определяется структурой ЧУМ;
    \item Все учитывающие эквивалентность алгоритмы в~ряде пределов
      приближаются к~$O(n^2)$.
  \end{itemize}
\end{frame}

\begin{frame}
  \frametitle{Граф состояний (State Graph)}
  \begin{block}{Структура данных}
    Граф состояний --- компактное и~полное представление всех возможных
    результатов исполнения многопоточной программы, позволяющее
    восстанавливать линейные порядки без их~явного хранения.
  \end{block}
  \begin{itemize}
    \item Объединяет эквивалентные промежуточные состояния при~анализе
      различных линейных расширений;
    \item Даёт возможность верификации программ с~большим числом
      конкурирующих обращений (десятки тысяч операций).
  \end{itemize}
\end{frame}

\begin{frame}
  \frametitle{Граф состояний и~трассы}
  \begin{block}{Соответствие}
    Порядок, восстанавливаемый из~истока графа состояний, является
    аналогом ``трассы'' (см.~теорию трасс), при этом по~построению
    \textbf{не~существует кандидатов, заведомо нарушающих аксиомы
    модели памяти}.
  \end{block}
  \begin{itemize}
    \item Классы эквивалентности графа состояний --- аналог трасс,
      но~в~терминах модели памяти $P$ и~зависимости $D$;
    \item Свойство единственности истока (лемма о~единственности пути)
      гарантирует отсутствие избыточности при~хранении состояний;
    \item Это свойство \textbf{строже}, чем у~трасс: недопустимые
      кандидаты не~строятся вовсе.
  \end{itemize}
\end{frame}

\begin{frame}
  \frametitle{Алгоритмы верификации}
  Предложены два подхода к~верификации соответствия аппаратуры
  заявленной модели памяти:
  \begin{enumerate}
    \item на основе анализа классов линейных порядков частично
      упорядоченного множества;
    \item на основе анализа графа состояний.
  \end{enumerate}
  \medskip
  Доказана эквивалентность данных подходов к~верификации.
\end{frame}

\begin{frame}
  \frametitle{Кластеризация и~насыщение}
  \begin{itemize}
    \item Предложен метод \textbf{кластеризации графа состояний}
      для декомпозиции задачи верификации на~независимые подзадачи;
    \item Введена \textbf{метрика насыщения}, позволяющая различать
      эффекты, обусловленные переупорядочиванием зависимых операций
      и~моделью памяти;
    \item Метрика насыщения позволяет останавливать исполнение программы
      при достижении полного покрытия кластеров состояний.
  \end{itemize}
\end{frame}

\begin{frame}
  \frametitle{Ограничения подхода}
  \begin{itemize}
    \item В~краевых случаях (например, $N$~ядер с~одним RMW на~общий
      адрес) задача сводится к~построению всех перестановок без
      повторений: асимптотика $\to O(N!)$;
    \item Построение порядков \\textbf{с~учётом} аксиом модели исключает
      порождение недопустимых кандидатов, то~есть построение
      \\textbf{негативных} тестовых сценариев в~рамках подхода
      невозможно.
  \end{itemize}
  \begin{alertblock}{Невозможность для RVWMO}
    Доказано, что не~существует формальной модели, разрешающей
    переупорядочивание видимости пересекающихся по~адресам операций
    внутри одного ядра: для теоретической модели, допускающей такое
    переупорядочивание, невозможно корректно определить транзитивное
    замыкание и~аксиомы (получено противоречие).
  \end{alertblock}
\end{frame}

\begin{frame}
  \frametitle{Цели и~полученные результаты}
  Поставленные задачи решены в~полном объёме:
  \begin{description}
    \item[Задача 1 ---> ] модель программы в~виде ЧУМ операций с~памятью
      с~учётом моделей памяти, разделяющая ограничения порядка~$P$
      и~зависимость операций~$D$;
    \item[Задача 2 ---> ] алгоритмы построения линейных порядков с~учётом
      классов эквивалентности перестановок (независимость, независимые
      последовательности, зависимость), не~порождающие недопустимых
      кандидатов;
    \item[Задача 3 ---> ] структура данных ``граф состояний'' для
      компактного и~полного представления результатов исполнения;
    \item[Задача 4 ---> ] алгоритмы верификации соответствия аппаратуры
      заявленной модели памяти (на~основе линейных порядков
      и~на~основе графа состояний).
  \end{description}
  Дополнительно созданы метод кластеризации графа состояний и~метрика
  насыщения.
\end{frame}
